Contributing to Mini Web

Thank you for your interest in contributing to Mini Web!

Mini Web is an open-source Android web browser focused on speed, privacy, security, and a smooth browsing experience.

We welcome bug reports, feature suggestions, improvements, and code contributions from developers.

1. How to Contribute

You can contribute in several ways:

- Report bugs and technical issues.
- Suggest new features and improvements.
- Improve the user interface and user experience.
- Fix existing bugs.
- Improve performance and security.
- Improve documentation.
- Submit code improvements through Pull Requests.

2. Getting Started

To contribute code:

1. Open the Mini Web GitHub repository.
2. Fork the repository to your GitHub account.
3. Clone your fork.
4. Create a new branch for your changes.
5. Make your changes.
6. Test your changes.
7. Commit and push your changes.
8. Open a Pull Request to the original repository.

3. Development Requirements

Mini Web is an Android application.

Development technologies include:

- Kotlin
- Android SDK
- Jetpack Compose
- Material 3
- Android WebView
- Gradle

Use the project's existing architecture and dependencies when making changes.

4. Code Guidelines

Please follow these guidelines:

- Write clean and readable Kotlin code.
- Use meaningful variable and function names.
- Follow the existing project structure.
- Avoid unnecessary dependencies.
- Preserve existing browser functionality.
- Handle errors safely.
- Avoid introducing unnecessary permissions.
- Keep the user interface responsive.
- Do not commit generated build files unnecessarily.

5. Testing

Before submitting a Pull Request:

- Verify that the project builds successfully.
- Test the affected features.
- Check that existing features continue to work.
- Test on an Android device or emulator when possible.
- Check GitHub Actions for build errors.

Do not submit code that knowingly breaks the application.

6. Pull Request Guidelines

When submitting a Pull Request:

- Use a clear and descriptive title.
- Explain what you changed.
- Explain why the change is needed.
- Include screenshots for UI changes when possible.
- Mention related issues.
- Ensure that your changes do not unnecessarily modify unrelated files.

All Pull Requests are subject to review before merging.

7. Bug Reports

When reporting a bug, include:

- A clear description of the problem.
- Steps to reproduce the issue.
- Expected behavior.
- Actual behavior.
- Android version and device information, if relevant.
- Screenshots or logs, when available.

8. Feature Requests

When suggesting a feature:

- Describe the proposed feature.
- Explain why it would be useful.
- Include examples or screenshots if helpful.
- Mention any possible limitations.

9. Security Issues

Please do not publish sensitive security vulnerabilities, passwords, API keys, signing keys, or private credentials in public issues or Pull Requests.

Report security concerns privately to the repository maintainer.

10. License

By contributing to Mini Web, you agree that your contributions will be licensed under the project's MIT License.

Please ensure that you have the right to submit any code or assets you contribute.

11. Community Guidelines

Please:

- Be respectful and professional.
- Welcome constructive feedback.
- Help other contributors.
- Avoid spam and unrelated discussions.
- Keep discussions focused on improving Mini Web.

12. Thank You!

Every contribution matters.

Thank you for helping make Mini Web better!
